# Documentación de Comandos del Proyecto LILY-GO

Este documento detalla todos los comandos disponibles en el sistema, su sintaxis y ejemplos de uso. Los comandos se envían a través del puerto serial.

## Convenciones
- Los comandos comienzan generalmente con el prefijo `DVL+`.
- Los parámetros se separan por comas u otros delimitadores según el comando.
- La mayoría de las configuraciones persisten en la memoria flash (Preferences) y se mantienen tras un reinicio.

---

## 1. Configuración del Sistema

### Identificación y Ubicación

| Comando | Descripción | Ejemplo |
| :--- | :--- | :--- |
| `DVL+ID=<id>` | Establece el identificador del dispositivo. También actualiza el tópico MQTT. | `DVL+ID=EQUIPO_01` |
| `DVL+SLAT=<lat>` | Establece la latitud del dispositivo. | `DVL+SLAT=-34.6037` |
| `DVL+SLONG=<lon>` | Establece la longitud del dispositivo. | `DVL+SLONG=-58.3816` |

### Trama de Datos y Comunicación

| Comando | Descripción | Ejemplo |
| :--- | :--- | :--- |
| `DVL+SFINI=<marker>` | Establece el marcador de inicio de la trama de datos. | `DVL+SFINI=DATA,` |
| `DVL+SFFIN=<marker>` | Establece el marcador de fin de la trama de datos. | `DVL+SFFIN=\r` |
| `DVL+SPARSE=<char>` | Establece el carácter separador de campos en la trama. | `DVL+SPARSE=;` |
| `DVL+STIME=<seg>` | Establece el intervalo de publicación de datos (en segundos). | `DVL+STIME=60` |
| `DVL+SKA=<seg>` | Establece el intervalo de publicación de la trama Keep Alive en segundos (por defecto `300`). | `DVL+SKA=300` |

### Habilitaciones (Flags)

| Comando | Descripción | Ejemplo |
| :--- | :--- | :--- |
| `DVL+EN_SENSOR` | Habilita la lectura del sensor principal. | `DVL+EN_SENSOR` |
| `DVL+EN_SERIAL=<0\|1\|2>` | Configura UART2: 0 deshabilitado, 1 lectura normal y 2 bridge/retransmisión. Los modos activos deshabilitan Modbus. | `DVL+EN_SERIAL=1` |
| `DVL+EN_MODBUS=<1\|0>` | Habilita (`1`) o deshabilita (`0`) la funcionalidad Modbus. Al habilitar, deshabilita `EN_SERIAL`. | `DVL+EN_MODBUS=1` |
| `DVL+EN_BLE=<1\|0>` | Habilita (`1`) o deshabilita (`0`) el escaneo y publicacion de sensores BLE. Al habilitar, deshabilita sensor, serial y Modbus. | `DVL+EN_BLE=1` |

### Actualización FOTA

| Comando | Descripción | Ejemplo |
| :--- | :--- | :--- |
| `DVL+FOTA=<url>` | Inicia una actualización de firmware Over-The-Air desde la URL especificada. | `DVL+FOTA=http://server.com/firmware.bin` |

### Control de Hardware

| Comando | Descripción | Ejemplo |
| :--- | :--- | :--- |
| `DVL+RESET` | Reinicia el dispositivo ESP32. | `DVL+RESET` |
| `DVL+EXP_RESET` | Reinicia la placa expansora (cicla la energía del pin `SENSOR_POWER_PIN`). | `DVL+EXP_RESET` |

## 2. Configuración ADC (Analógico)

Estos comandos permiten calibrar y configurar el comportamiento de las entradas analógicas (ADC0 y ADC1).

### Filtro (`SFIL`)
Configura un filtro de umbral mínimo.
- **Sintaxis:** `DVL+SFIL=n,m,p`
  - `n`: Índice del canal (0-1).
  - `m`: Umbral mínimo.
  - `p`: Valor de reemplazo si la lectura <= `m`.
- **Ejemplo:** `DVL+SFIL=0,0.5,0.0` (Si ADC0 <= 0.5, leerá 0.0).

### Factor de Calibración (`SFACTOR`)
Ajusta la lectura con una ecuación lineal: `Valor = (Lectura * m) + p`.
- **Sintaxis:** `DVL+SFACTOR=n,m,p`
  - `n`: Índice del canal (0-1).
  - `m`: Pendiente (factor multiplicativo).
  - `p`: Offset.
- **Ejemplo:** `DVL+SFACTOR=1,1.05,0.2`

### Alisado (`SALI`)
Configura el número de muestras para el promedio móvil.
- **Sintaxis:** `DVL+SALI=<val>`
- **Ejemplo:** `DVL+SALI=50` (Promedio de 50 muestras).

### Tiempo de Muestreo (`STADC`)
Configura cada cuánto se toma una muestra ADC (multiplicador de 100ms).
- **Sintaxis:** `DVL+STADC=<val>`
- **Ejemplo:** `DVL+STADC=10` (10 * 100ms = 1 segundo).

## 3. Configuración Modbus

Permite definir tramas Modbus para ser consultadas periódicamente.

### Paridad de Modbus
- `DVL+SPARITY_MODBUS=NONE`, `DVL+SPARITY_MODBUS=EVEN` o `DVL+SPARITY_MODBUS=ODD`: configura la paridad y la guarda. El valor inicial es `NONE`.
- `DVL+QPARITY_MODBUS`: consulta la paridad guardada; por ejemplo, `PARITY_MODBUS=EVEN`.
- `DVL+SBAUD=<baud>` cambia la velocidad compartida sin modificar la paridad. Serial común usa 8N1; Modbus usa 8N1, 8E1 o 8O1 según la paridad guardada.
- `DVL+SENVIO_MODBUS=COLA` o `DVL+SENVIO_MODBUS=DIRECTO`: selecciona y guarda el envio de los reportes Modbus. Por defecto es `DIRECTO`, como antes. En `COLA`, si hay historicos pendientes, los nuevos reportes por cambio y por STIME se agregan al final de la cola existente; con cola vacia se publican directamente si MQTT esta conectado. Sin MQTT se guardan en ambos modos. No cambia la descarga de historicos ni los demas reportes.
- `DVL+QENVIO_MODBUS`: consulta el modo guardado; responde `ENVIO_MODBUS=COLA` o `ENVIO_MODBUS=DIRECTO`.
- El MQTT Modbus incluye `baud` y `paridad`. `datos_hexa` conserva el orden de bytes recibido.
- Si serial está activo, la paridad Modbus se guarda pero serial sigue en 8N1.
  Al habilitar Modbus se aplica su paridad guardada. Ambos valores se recuperan
  tras reiniciar. No se agregan comandos para bits de datos o parada.
- Un valor distinto de NONE/EVEN/ODD se rechaza sin cambiar la configuración.

Ejemplo: 4800 baud, 8E1 (8 bits, EVEN, 1 bit de parada):
```text
DVL+SBAUD=4800
DVL+SPARITY_MODBUS=EVEN
DVL+MODBUS=1,1,3,36,2
DVL+EN_MODBUS=1
DVL+QBAUD
DVL+QPARITY_MODBUS
DVL+QMODBUS
```

### Configurar Trama
- **Sintaxis:** `DVL+MODBUS=idx,ID,FUNC,ADDR,QTY`
  - `idx`: Índice de la trama (1-25).
  - `ID`: ID del esclavo Modbus.
  - `FUNC`: Código de función.
  - `ADDR`: Dirección de memoria inicial.
  - `QTY`: Cantidad de registros.
- **Ejemplo:** `DVL+MODBUS=1,1,3,100,2` (Trama 1: Esclavo 1, Función 3, Dirección 100, 2 Registros).
- Usar decimales sin ceros iniciales o hexadecimal con `0x`. La base automática
  interpreta un cero inicial como octal: ocho se escribe `8` o `0x08`, no `08`.

El primer parámetro (`idx`) identifica la consulta (1-25) y el sufijo del tópico:
`DVL/LILY-GO/<ID_EQUIPO>/MODBUS/<idx>`. Se publica un mensaje por consulta,
incluso si varias consultan al mismo ID Modbus. El primer byte de `consulta`
identifica al dispositivo. El tópico ya no se identifica por el ID del sensor.

`consulta` contiene la trama TX completa con CRC; `respuesta`, la última trama
RX válida con CRC; `datos_hexa`, solo sus bytes de datos en hexadecimal compacto;
`date_respuesta`, la fecha UTC del reloj al recibir esa respuesta válida.
`date` indica cuándo se armó el mensaje MQTT. Se retiran los campos `addr...`.
Ante timeout, respuesta de otro ID, CRC o longitud inválidos o excepción, se
conservan la respuesta válida anterior, sus datos y su fecha. Hasta recibir una
lectura válida, esos tres campos están vacíos. Si el reloj aún no tiene un año
admisible (2024-2099), el dato se guarda con fecha vacía. La limpieza por cambio
de consulta, baud o paridad también limpia su fecha; el histórico flash queda.
Las lecturas están en RAM y no se recuperan después de reiniciar.

Cada consulta publica también al recibir su primera respuesta válida o cuando cambian sus bytes de datos (datos_hexa) respecto de la última respuesta válida de ese idx. Una respuesta igual actualiza date_respuesta sin disparar otro envío; timeout, trama inválida o excepción no disparan el evento. Se conserva el mismo JSON y topic por idx. La publicación periódica por DVL+STIME y el keep-alive siguen independientes. Si el evento no puede publicarse, se intenta encolar en la flash existente, con su límite de 511 bytes por mensaje y su capacidad finita; los paquetes más antiguos pueden sobrescribirse al llenarse la cola. El evento se procesa antes de la siguiente consulta, sin esperar STIME. No se agregan comandos ni se cambia el orden de los datos.

Se mantienen 200 ms de espera, polling de 2 s y el límite de 511 bytes por
mensaje offline. Los paquetes históricos pendientes mantienen el formato previo.

### Borrar Trama
- **Sintaxis:** `DVL+MODBUSCLR=<idx|ALL>`
- `idx` debe estar entre 1 y 25, tanto para configurar como para borrar. Se
  valida antes de convertirlo a 8 bits: 0, 26, 257 o texto inválido se rechazan.
  Solo `ALL` borra todas las consultas.
- **Ejemplo:** 
  - `DVL+MODBUSCLR=1` (Borra la trama 1).
  - `DVL+MODBUSCLR=ALL` (Borra todas las tramas).

## 4. Comandos de Consulta (Query)

Estos comandos devuelven el estado actual de las configuraciones.

| Comando | Retorna (Ejemplo) | Descripción |
| :--- | :--- | :--- |
| `DVL+VER` | `VERSION=V07.19.05` | Versión del firmware. |
| `DVL+QTIME` | `TIME=60` | Intervalo de publicación. |
| `DVL+QKA` | `KEEP_ALIVE=300` | Intervalo de publicación de la trama Keep Alive (segundos). |
| `DVL+QEVT=<id>` | `EV0=1,VPRIN,<,11.50,30,MQTT,ONESHOT` | Configuración de la regla de evento `<id>` (`0..3`). |
| `DVL+EVT_STATUS` | *(Tabla por Serial/RESPUESTA)* | Estado en vivo de `EV0..EV3`, `DT0..DT3` y reloj `RTC`. |
| `DVL+QDT=<id>` | `DT0=2026-11-20 08:30:00 (ESTADO=0)` | Programación y estado del disparador fecha/hora `<id>` (`0..3`). |
| `DVL+QDT` | `RTC=...` / `DT0..DT3` | Hora `RTC` actual y listado de los 4 disparadores fecha/hora. |
| `DVL+QBAUD` | `BAUD=4800` | Velocidad compartida de UART2. |
| `DVL+QPARITY_MODBUS` | `PARITY_MODBUS=EVEN` | Paridad Modbus guardada. |
| `DVL+QENVIO_MODBUS` | `ENVIO_MODBUS=DIRECTO` | Modo de envio Modbus guardado. |
| `DVL+QLAT` | `LAT=-34.xxx` | Última latitud configurada. |
| `DVL+QLONG` | `LONG=-58.xxx` | Última longitud configurada. |
| `DVL+QFINI` | `START_MARKER=DATA,` | Marcador de inicio. |
| `DVL+QFFIN` | `END_MARKER=\r` | Marcador de fin. |
| `DVL+QPARSE` | `SEPARATOR=,` | Separador de trama. |
| `DVL+QEN_SENSOR`| `EN_SENSOR=1` | Estado de lectura de sensor. |
| `DVL+QEN_SERIAL`| `EN_SERIAL=0` | Estado de puerto serial secundario. |
| `DVL+QEN_MODBUS`| `EN_MODBUS=1` | Estado de Modbus. |
| `DVL+QEN_BLE` | `EN_BLE=1` | Estado del escaneo y publicacion de sensores BLE. |
| `DVL+QMODBUS` | `[OK] MODBUS#1 ID=0x01 FUNC=0x03 ADDR=0x0064 QTY=0x0002` | Lista la configuración Modbus. |
| `DVL+QFIL` | `FIL0=...` | Configuración de filtros ADC. |
| `DVL+QFACTOR` | `FAC0=...` | Configuración de factores ADC. |
| `DVL+QTADC` | `TIME ADC=10` | Tiempo de muestreo ADC. |
| `DVL+QALI` | `ALISADO=50` | Valor de alisado ADC. |

## 5. Comandos de Expansora (`EXP+`)

Cualquier comando que comience con `EXP+` será retransmitido tal cual al puerto serial secundario (`SensorSerial`). El sistema espera una respuesta de la expansora por hasta 5 segundos.

- **Sintaxis:** `EXP+<cualquier_comando>`
- **Ejemplo:** `EXP+LEER` (Envía "EXP+LEER" a la expansora y devuelve su respuesta).

## 6. Motor de Eventos (Micro-PLC) y Disparadores Fecha/Hora

Permite programar hasta **4 reglas determinísticas** (`EV0`..`EV3`, evaluadas cada 100 ms con temporizador TON persistido en NVS) y **4 disparadores por fecha y hora** (`DT0`..`DT3`). Las alertas se publican de inmediato en `DVL/LILY-GO/<ID_EQUIPO>/EVENTOS` (o en Flash si no hay enlace MQTT).

### Configurar Regla de Evento (`DVL+SEVT`)
- **Sintaxis:** `DVL+SEVT=<id>,<en>,<src>,<op>,<th>,<ton>,<act>,<trg>` (o `DVL+SEVT=<id>,0` para deshabilitar).
  - `<id>`: Regla `0..3`.
  - `<en>`: `1` (activa) o `0` (inactiva).
  - `<src>` (fuentes soportadas):
    - Alimentación y Analógicos: `VPRIN`, `VBACK`, `ADC0`, `ADC1`.
    - Digitales y Enlace: `DI1` (`GPIO13`), `DI2` (`GPIO14`), `COMM` (estado MQTT).
    - Sensores Cableados: `TEMP` (DS18B20), `S0`..`S15` (canales expansora serial).
    - Sensores BLE Moko (con filtro opcional por MAC completa o últimos 4 hex `:<mac>`): `BLE_DOOR[:<mac>]`, `BLE_MOV[:<mac>]`, `BLE_TEMP[:<mac>]`, `BLE_HUM[:<mac>]`, `BLE_BAT[:<mac>]`.
    - Salud ESP32: `TEMP_MCU`, `HEAP`, `BTN` (`GPIO0`).
    - Disparadores Fecha/Hora: `DT0`..`DT3` (alias `TIME0`..`TIME3`, `DATE0`..`DATE3`).
  - `<op>`: `>`, `<`, `>=`, `<=`, `==`, `!=`.
  - `<th>`: Umbral numérico.
  - `<ton>`: Confirmación continua en segundos (`0..86400`).
  - `<act>`: `MQTT`, `OUT:<pin>:HIGH`, `OUT:<pin>:LOW`, `OUT:<pin>:PULSE:<seg>`, `CYCLE_PWR` (`GPIO23`), `RESTART`.
  - `<trg>`: `ONESHOT` o `REPEAT:<seg>`.
- **Ejemplos:**
  - `DVL+SEVT=0,1,VPRIN,<,11.5,30,MQTT,ONESHOT`
  - `DVL+SEVT=1,1,BLE_DOOR:F074BFF03C91,==,1,5,OUT:15:PULSE:30,ONESHOT`
  - `DVL+SEVT=2,1,DT0,==,1,0,OUT:15:PULSE:20,ONESHOT`

### Consultas y Estado del Motor
- `DVL+QEVT=<0..3>`: Devuelve la regla configurada (`EV<id>=...`).
- `DVL+EVT_STATUS`: Imprime el estado en vivo de `EV0..EV3`, lecturas actuales, progreso TON, salidas y bloque `DT0..DT3`.

### Configurar y Consultar Disparadores Fecha/Hora (`DVL+SDT` / `DVL+QDT`)
- **Sintaxis:** `DVL+SDT=<0..3>,<fecha_hora|0>`
  - Fecha y hora puntual: `YYYY-MM-DD HH:MM:SS` (o `YYYY-MM-DD HH:MM`).
  - Horario diario recurrente: `HH:MM:SS` o `HH:MM` (equivale a `*-*-* HH:MM:SS`).
  - Comodines por campo (`*`): ej. `*-*-01 12:00:00` (día 1 de cada mes).
  - Deshabilitar índice: `DVL+SDT=<0..3>,0` (o `OFF`).
- **Consultas:** `DVL+QDT=<0..3>` (índice individual y estado `0`/`1`) y `DVL+QDT` (reloj `RTC` actual + `DT0..DT3`).
- **Ejemplos:**
  - `DVL+SDT=0,08:00:00`
  - `DVL+SDT=1,2026-11-20 14:30:00`
